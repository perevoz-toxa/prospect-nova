# Prospect Nova

Роман. Русский язык. Глава = 3000 слов = 3 сцены по ~1000.

> **Принцип конвейера:** слабый генератор компенсируется дисциплиной.
> Прогресс = проверенные артефакты, а не объём текста.
> Фактлист — контракт главы. Проза, state и канон производны от контракта.
> Ворота закрыты по умолчанию: нет чистого аудита — нет коммита.

## Быстрый старт

```bash
cd D:/Development/books/prospect-nova
pi
/trust      # разрешить .pi/ (один раз)
/reload     # после любых правок в .pi/
```

Модель по умолчанию — `strata/swift-1.5-iq2_xs`. Всё работает локально, GLM не обязателен.

## Цикл написания главы

```
/next            → 3 варианта следующего хода. СТОП.
  ты: 1 / 2 / 3 / своё развитие
/apply N         → дирижёр полного прогона:
    ├─ /sheet N    карточка + фактлист        ← СТОП: ты утверждаешь лист
    ├─ /write N    бит за битом + проверки
    ├─ /check N    холодный читатель: диф фактлиста
    │      ├─ провалы → /fix N → /check N (до 3 кругов)
    │      └─ чисто  → дальше
    └─ /accept N   ворота: state из фактлиста → decisions → git commit
```

Две точки, где решает человек: **выбор варианта** и **утверждение фактлиста**. Всё остальное — конвейер с воротами.

Можно вызывать шаги и по одному: `/sheet 1`, потом `/write 1`, потом `/check 1`...

## Что делает каждый шаг

| Команда | Модель | Выход |
|---|---|---|
| `/next [фокус]` | swift | 3 варианта хода. Ничего не пишет |
| `/sheet N` | swift | `plan/scene-cards/chNN.md` + `plan/sheets/chNN.md` (контракт). Ждёт утверждения |
| `/write N` | swift | `draft/chNN.md`: бит → wc/grep → следующий бит. Не коммитит |
| `/check N` | qwen (быстрее) | Реконструкция фактов только из текста → таблица вердиктов → механика → вопросы читателя |
| `/fix N <что>` | swift | Точечный ремонт проваленных битов |
| `/accept N` | — | state из фактлиста, canon-дифф, decisions, commit |
| `/apply N` | — | полный прогон с остановками |

## Уровень арки (когда накопились главы или меняется замысел)

```
/arc             → слабые места + вопросы автору. СТОП.
  ты отвечаешь на вопросы (можно спорить, можно «не знаю, предложи»)
/arcplan "ответы" → 3 арки разной формы. СТОП.
  ты: номер или своя форма
/beats <выбор>   → арка прописывается в биты, коммит
```

`/arc` стоит гонять на GLM (читает все главы), но работает и локально до ~15 глав.

## Пересборка состояния

`/state` — пересчитать `story/state.md` из глав (после ручных правок текста).

## Структура

```
story/
├── state.md              # где история. Обновляется ТОЛЬКО /accept, из фактлиста
├── plan/
│   ├── synopsis.md       # замысел книги
│   ├── beats.md          # биты (бит = глава = 3 сцены)
│   ├── scene-cards/      # карточки сцен
│   └── sheets/           # ФАКТЛИСТЫ — контракты глав
├── canon/                # персонажи, мир, хронология, лексикон
└── draft/                # главы
notes/
├── decisions.md          # журнал решений
└── rejected.md           # отвергнутые варианты (топливо)
archive/
└── test-run-1/           # первый тестовый прогон (git tag test-run-1)
.pi/                      # команды и правила агента
```

## Модели

| Модель | Роль |
|---|---|
| `strata/swift-1.5-iq2_xs` | `/next`, `/sheet`, `/write`, `/fix` — решения и проза |
| `lm-studio/qwen/qwen3.6-35b-a3b` | `/check`, `/state` — быстрые механические проверки |
| `zai/glm-5.3` (опционально) | `/arc`, `/arcplan`, полировка — большой контекст, дорогие суждения |

Смена модели в сессии: `/model <провайдер/модель>`. Для «честного» холодного читателя — отдельный прогон без контекста:

```bash
pi --model lm-studio/qwen/qwen3.6-35b-a3b --print @story/draft/ch01.md \
  "Восстанови из текста: что за место, что нашли, как поняли, кто за этим, что теперь. Только из текста."
```

## Как проходить главу (шпаргалка)

1. `/next` → выбрал (или своё).
2. `/apply N` → на `/sheet` читаешь **фактлист**: каждый факт — с ожиданием, наблюдением, выводом, репликой, терминами. Правь прямо в файле, потом «утверждаю».
3. `/write` идёт сам, бит за битом. Смотри объёмы битов.
4. `/check`: смотри таблицу вердиктов. Провалы → `/fix`. Максимум 3 круга.
5. `/accept`: state обновился из листа, commit создан. Глава закрыта.
6. После главы — 2 минуты ретро (см. ниже).

## Ретро: как прокачивать конвейер

После каждой главы спроси себя (или агента): какие факты падали в `/check` и почему?

- факт «отсутствует» → лист был перегружен или бит слишком большой → уменьшай факты на бит;
- факт «искажён» → в промпте `/write` не хватает правила → допиши правило в `.pi/prompts/write.md`;
- модель игнорирует запрет → переноси запрет в начало промпта, формулировки короче;
- систематически одно и то же → правило в `.pi/APPEND_SYSTEM.md`.

Промпты — обычные файлы в git. Правка промпта = коммит «конвейер: <что ужесточено>».

## Правила (защита от дрейфа)

- Агент не пишет файлы до утверждения (роли команд — в `AGENTS.md`).
- `story/canon/` агент не редактирует — только diff.
- `story/state.md` обновляется только `/accept` и только из фактлиста.
- Коммит главы = формулировка решения, не «обновил файлы».
